DTC Diagnostic System continuous monitors · pending → confirmed · freeze frame
Monitors run automatically in the background (like a real drive cycle) and evaluate symptoms — fuel-trim saturation, sensor plausibility, circuit continuity — not the fault switches directly. A code goes PENDING on the first failed check and CONFIRMED after a second consecutive failure, capturing a freeze frame at confirmation.

Intelligent Fault Diagnosis (Heuristic) multi-signal correlation
Cross-references DTC monitor states with sampled fuel-trim behaviour at idle, mid-load and WOT to rank likely root causes with a confidence score — the same kind of symptom correlation a diagnostic technician would use to tell, say, a vacuum leak apart from a clogged injector even though both saturate fuel trim rich.

Auto-Tune (Adaptive Learning): walks the closed-loop-eligible cells (load ≤ 90%), reads the same lambda feedback the ECU would use, and nudges the calibrated VE map toward the value that would zero the fuel trim error — the same mechanism real ECUs use for long-term fuel trim learning of the speed-density backup table. It trusts the O2 sensor: if O2 is faulted while you run Auto-Tune, it will learn an incorrect map. WOT (100% load) is intentionally skipped since real ECUs run open-loop there and that row is normally set from dyno data. A before/after comparison measures the improvement in speed-density fallback accuracy (i.e. accuracy if MAF ever fails), since that is the path the VE table actually governs while MAF is healthy.
